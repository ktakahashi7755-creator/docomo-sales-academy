# Testing Standards

`CLAUDE.md` §6 Phase0/3/6 を正典に要約。**「動くはず」で終わらせない。実際に通す。**

## 単体（Vitest）
- 採点・合格判定などのロジックは**純粋関数に切り出して** Vitest でテスト。UI と密結合させない。
- **境界値必須**。合格点ロジックは 79/80（通常80）・89/90（重要90）・99/100（コンプラ100）を必ず網羅。
- 異常系・空入力・null 分岐も対象。テストは振る舞いを検証し、実装の写経にしない。

## RLS ポリシー
- 越権不可をテストで確認（他人のデータが取得/更新できないこと、SV の閲覧可・編集不可など）。
- 役割（admin/sv/trainee/helper/closer）ごとの可視性を検証。

## E2E（Playwright）
- 主要フローを担保: ログイン / 受験合格 / ロープレ完走 / 管理編集→反映 / 認定。

## CI と完了条件
- `typecheck` 0・`lint` 0・関連 `unit` 緑・`build` 成功・該当時 E2E 緑が**完了条件**。CI を緑にしてからフェーズを閉じる。
- 大量出力（テスト全実行・横断調査）はサブエージェント文脈に閉じ込め、親には失敗点と再現手順だけを返す。
