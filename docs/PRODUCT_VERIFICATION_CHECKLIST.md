# 商材 公式数値 検証ワークシート（要確認の解消用）

> 目的：`freshnessStatus: needs_review` の商材を、公式の確定値で `verified` 化する。
> エージェント環境からは docomo / ahamo / dcard 各サイトが 403 で取得できないため、
> **公式ページを確認できる方（高橋・現場）が本表を埋めて返す**運用とする。捏造はしない。

## 使い方

1. 各商材の「公式URL」を実際に開く。
2. 「現状の記載値（要確認）」と公式の最新表示を突き合わせる。
3. 「最新値（公式）」「確認日」を記入し、一致なら「判定」に `verified`、相違があれば正しい値を記入。
4. 本表を Claude に渡す → `src/data/seed.ts` の数値・`officialCheckedAt`・`freshnessStatus` を更新し、
   関連レッスン本文・クイズ解説も追従させる（data-integrity 検証つき）。

> 補足：料金・還元・補償・キャンペーン条件は変動する。`実質` 額は前提条件（対象決済・ポイント充当・
> 割引適用）とセットで確認すること。キャンペーンは恒常制度と分けて記録する。

## 反映の流れ（Claude側）

本表が埋まったら、Claude が以下を実施する：

1. `src/data/seed.ts` の対象商材の `benefits`/`warnings`/`pitch` 等の数値を最新値へ更新。
2. `officialCheckedAt` を確認日に更新し、一致確認できたものは `freshnessStatus: "verified"`（または明示を外して日付判定に委ねる）。
3. 数値が変わった場合、`src/growth/data/curriculum.ts` の関連レッスン本文・`src/data/quiz.ts` の解説も追従。
4. `data-integrity-steward` 検証 → `docs/AUDIT.md` 更新 → typecheck/lint/test/build → コミット。

> 公式ページのテキスト（料金表部分）をそのまま貼っていただく形でも対応可能です。
> その場合は該当箇所を抜き出して上表に反映します。
