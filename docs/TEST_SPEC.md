## 1. テスト方針

1. **ロジックは純粋関数化して境界値まで単体テスト**（採点・合否・鮮度・進捗）
2. **データはテストで機械的に守る**（ID一意・件数・網羅・正典整合）— 目視レビューに依存しない
3. **主要フローは実ブラウザE2E**（mobile Pixel 7 / desktop Chrome の2プロファイル）
4. **ビジュアルは全画面スクリーンショット走査**（リリース前に30画面×2）
5. ゲート：`typecheck 0 / lint 0 / unit全緑 / E2E全緑 / build成功` を満たさない変更はマージ不可

## 3. 単体テスト仕様（代表）

### 3.1 採点 `gradeQuiz`（境界値必須）

| ケース   | 入力                     | 期待                                                        |
| -------- | ------------------------ | ----------------------------------------------------------- |
| 全問正解 | 5/5一致                  | 100・passed(80)=true・passed(100)=true                      |
| 合格境界 | スコア79/80/89/90/99/100 | 79<80不合格、80合格、90合格(90)、99<100不合格、100合格(100) |
| 複数選択 | 部分一致・過剰選択       | 不正解（集合完全一致のみ正解）                              |
| 未回答   | answers欠落              | その設問は不正解として採点                                  |

### 3.2 鮮度 `freshnessOf`（90日閾値）

| ケース               | 期待                        |
| -------------------- | --------------------------- |
| 明示 `needs_review`  | 日付に関わらず needs_review |
| 89日/90日経過        | verified                    |
| 91日経過             | needs_review                |
| 日付不正（"不明"等） | needs_review（安全側）      |

### 3.3 データ整合（機械保証）

- クイズ：ID重複なし・correct indexが choices 範囲内・各モジュール件数
- カバレッジ：**全19レッスンに quizModuleId**・参照先モジュール実在・**各3問以上**・p1m4合格点=100
- 現場ガイド：プロセス15連番一意／場面15・ヒアリング19・反論17・ルーブリック12・育成10／必須フィールド非空／反論IDは `fg-obj-*` 名前空間（seedと衝突しない）
