## 1. 背景と目的

### 1.1 背景

プロバイド株式会社は携帯・通信販売（ドコモ商材）の販売人材を育成している。未経験者の育成は現場OJTに依存しており、次の課題がある。

- 教育の質が指導者により ばらつく／体系化されていない
- 料金・還元などの事実値が口伝で伝わり、誤案内・コンプライアンス事故のリスクがある
- 研修生の到達度を客観的に測る手段がなく、現場投入の判断が属人的

### 1.2 目的

完全未経験者を**ドコモショップ店内販売ヘルパー／イベント／外販／軒先販売、最終的に認定クローザー**として稼働できる水準まで育成する実践型トレーニングWebアプリを提供する。「商品説明アプリ」ではなく、**現場の意思決定を支える営業OS**（座学→確認テスト→ロープレ→現場チェック→SVレビューの循環）を目指す。

### 1.3 スコープ

| 区分   | 内容                                                                                         |
| ------ | -------------------------------------------------------------------------------------------- |
| 対象   | 学習アプリ本体（教材・テスト・ロープレ・現場ガイド・進捗）、SV機能、AI評価、商材ナレッジ管理 |
| 対象外 | 人事評価・給与連携、店舗基幹システム連携、顧客個人情報の取り扱い（教材内でも扱わない）       |

## 2. 利用者（ペルソナ）と利用シーン

| 利用者                 | 特性                                   | 主な利用シーン                                                       |
| ---------------------- | -------------------------------------- | -------------------------------------------------------------------- |
| 研修生（未経験）       | 学生・第二新卒含む。専門用語を知らない | 通勤・待機時間にスマホで学習。ロープレで練習し、現場前にガイドで復習 |
| 現場ヘルパー           | 稼働中。弱点を補強したい               | 反論処理・場面別トークを現場で「引く」                               |
| SV（スーパーバイザー） | 複数研修生を指導                       | 進捗・弱点・認定可否を確認し、朝礼/終礼のレビューに使う              |
| 管理者                 | 教材・商材の鮮度に責任を持つ           | 商材数値の更新、キャンペーン期限の管理                               |

## 4. 非機能要件

| ID    | 分類             | 要件                                                                                                                                                   |
| ----- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| NFR-1 | ユーザビリティ   | モバイルファースト（〜380pxで崩れ・横スクロールなし）。主要操作は親指圏・最小タップ44px。「次の一段」が常に見える                                      |
| NFR-2 | アクセシビリティ | キーボード操作可・フォーカス可視・コントラストAA・prefers-reduced-motion尊重                                                                           |
| NFR-3 | 性能             | 初回表示を軽量に（gzip 150KB目安）。Lighthouse 90+（M5判定）                                                                                           |
| NFR-4 | 可用性           | 静的配信＋PWA（オフライン閲覧はSWキャッシュのSWR）                                                                                                     |
| NFR-5 | セキュリティ     | AIキー・service_roleは必ずサーバー側。フロントはanonキーのみ。RLSで本人/権限者限定                                                                     |
| NFR-6 | コンプライアンス | 事実値は公式URL＋最終確認日を正とし捏造しない。断定表現（必ず安くなる/実質0円/どこでも使える等）を教材・UIに置かない。パスワード・認証コードは本人入力 |
| NFR-7 | 保守性           | any禁止・型安全。教材/商材/プロセス/反論等はデータ分離。回帰テスト（単体125+・E2E12+）で保護                                                           |
| NFR-8 | 文体             | 絵文字を使わない。能動態・未経験者に分かる言葉で、内容はプロレベル                                                                                     |

## 5. 制約条件

1. 事実値の正典：dカードGOLD合計訴求「割引約6,600円＋ポイント約12,000P＝年間約18,600円相当」（POP準拠）、PLATINUM切替「実質18,700円」は固定。変更は公式根拠＋PO承認が必要
2. 公式サイト（docomo/ahamo/dcard）は開発環境から自動照合不可（403）。数値確定は人手ワークシート運用（PGA-OPS-001 §4）
3. 技術構成：React 18 / TypeScript / Vite / Tailwind CSS / React Router / Supabase。デザインはProvide基調（青系・white card）を固定
4. 配信：GitHub Pages（デモ）→ 本番はSupabase接続構成で同一コードベース
