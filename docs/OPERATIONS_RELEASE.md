## 2. リリース手順（自動）

1. 開発ブランチへ push → CI（typecheck/lint/format/unit/build/E2E）が実行
2. `pages.yml` が dist をビルドし GitHub Pages へ自動デプロイ（約1分）
3. 確認：Actions で `Deploy to GitHub Pages` が success → 実機URLをリロード（SWはSWR方式のため、更新は再読み込みで反映）

ロールバック：問題コミットを `git revert` して push（再デプロイで復旧）。

## 3. 日常運用

- [ ] Actions の CI/Deploy が緑であること
- [ ] `docs/AUDIT.md` の🔴が残っていないこと

### 3.2 学習データ（デモ期間）

- 進捗は**各端末の localStorage** に保存（`provide.entered` / `provide.userName`）。端末変更で引き継がれない旨を研修生に案内する（M2で解消）

## 4. 商材数値の鮮度運用（最重要）

> 事実値は公式が正。**推測で埋めない・断定しない**。

1. **トリガー**：(a) 90日経過で自動的に「要確認」表示（`freshnessOf`）／(b) キャンペーン開始・終了／(c) 現場からの誤り報告
2. **確認**：`docs/PRODUCT_VERIFICATION_CHECKLIST.md` の該当商材を公式URLで照合し、最新値・確認日を記入
3. **反映依頼**：記入済みワークシートを開発（Claude）へ渡す → seed更新・`officialCheckedAt`更新・verified化・関連教材/クイズ追従・data-integrity監査・デプロイまで実施
4. **緊急時**（誤案内リスク）：該当商材の `freshnessStatus: "needs_review"` を即時付与してデプロイ（UIに要確認が出る）→ その後正規手順

対象商材と現況は AUDIT A-D10/A-D11/A-D14 を参照。

## 5. 教材の更新運用

| 更新対象             | 場所                            | ルール                                                                                     |
| -------------------- | ------------------------------- | ------------------------------------------------------------------------------------------ |
| レッスン本文・トーク | `src/growth/data/curriculum.ts` | 変動数値は書かない（商材マスター参照）。絵文字・断定表現禁止                               |
| 確認テスト           | `src/data/quiz.ts`              | 正解位置を分散・誤答は現実的near-miss・各モジュール3問以上を維持（カバレッジテストが強制） |
| 現場ガイド           | `src/growth/data/*.ts`          | 件数・ID規約はテストが強制。反論IDは `fg-obj-*`                                            |
| お知らせ             | `ANNOUNCEMENTS`                 | 日付降順・tone（info/event/caution）                                                       |

すべての更新は CI 緑＋レビュー（該当時 design/data-integrity）を通してからマージする。

## 6. インシデント対応

| 事象                      | 一次対応                                               | 恒久対応                           |
| ------------------------- | ------------------------------------------------------ | ---------------------------------- |
| 画面が真っ白/旧画面が出る | 再読み込み（SW更新）。直らなければ直前コミットをrevert | E2E/ビジュアル回帰に再現ケース追加 |
| 教材の事実誤り報告        | §4緊急時手順（要確認化）                               | ワークシート照合→修正→監査記録     |
| CI赤                      | 該当ログで原因特定（テスト仕様書§7）                   | 修正＋回帰テスト追加               |
| Supabase障害（M2〜）      | デモモード（env無効化）で閲覧継続可                    | ステータス確認・復旧後に同期       |

## 7. アカウント・権限（M2〜運用開始時に確定）

- ロール：admin / sv / trainee / helper / closer（RLSで学習データは本人＋SV/adminのみ）
- SVの認定承認は certifications への承認記録として残る（audit_logs併記）
- 退職者はプロファイル無効化（is_active=false）。個人データの削除依頼はPOが受け付け、DBから削除
